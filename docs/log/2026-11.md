## 2026-11-11: the sleep lock on both sides, and the refusal beside a Linux already there, built (roadmap item 16; R33, R39, R24)

**Keeping the computer awake (roadmap item 16, R33).**

- **Windows.** `upgrade_scan::awake::hold()` calls `SetThreadExecutionState`
  (Windows' own "this thread still needs the system" call) for the system
  and the screen, continuous (`0x80000003`). The screen is held too because
  on a Modern Standby computer the screen going dark is what starts the
  sleep; the one click test's own lock held the system only. The request
  ends with the thread, so a program that crashes leaves the computer free
  to sleep. It is called first thing in `upgrade-scan`, `upgrade-harvest`,
  `upgrade-job`, `upgrade-prologue`, `upgrade-stick` and `upgrade-fetch`,
  and on each of the window's worker threads. `upgrade-gate`, which runs
  from the way-back stick before Windows Setup, is unchanged.
- **Linux.** `settle-in`'s new `awake` module takes one logind inhibitor
  (`systemd-inhibit`: sleep, idle and the lid switch; sleep and idle alone
  when the lid is turned down). The command under the lock is
  `tail --pid=<settle-in>`, so the lock is given back when the work ends
  and also when settle-in exits or is killed. The walk-away's prepare takes
  it and writes what was held as a step named `awake` in its record. The
  file pull's and reclaim's own inhibitors (`sleep infinity`, which was
  left running after a kill) are replaced by it.
- **What it cannot stop.** A closed lid on Windows, the power button, a
  flat battery. The Convert screen now says "Keep the lid open and the
  charger plugged in until Linux has started" (draft words).

**What it proved.** Plumbing (rule #5). Ubuntu's own signed GRUB reads
the kit's menu from `boot/grub/grub.cfg` with Fedora's menu sitting in
`EFI/BOOT`, writes the mark, and with `converted` on the stick starts the
installed Ubuntu instead of the installer, all with Secure Boot on.
settle-in, written for any Linux, installed and finished its first start
on Ubuntu. A disc taken whole lands file for file.

**What it did not prove.** Nothing on the Windows side has run with an
Ubuntu stick: not the window, not the prologue's start, not the handoff.
No real stick, no real internet, no real machine. No Wi-Fi (the rig has
none; settle-in wrote the connection, nothing joined it). Windows was
not started after line 17. Reclaim is not built for Ubuntu.
